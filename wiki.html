01 · WHY

The idea

Games are the medium. Mathematics is the learning. Human values are the background.

Maths for All is a free learning space for children with different ways of seeing, hearing, moving, reading, concentrating and learning.

We are not trying to remove the mathematics. We are trying to make mathematics easier to enter.

02 · FEEL

Learning philosophy

Act first. Let the learner encounter the mathematical idea through an activity.
Mistakes are information. A surprising or wrong attempt opens another path instead of closing the door.
Do not manufacture pressure. Speed matters only when the mathematics genuinely calls for it.
Let values emerge. Patience, fairness, curiosity and perseverance live inside the mechanics.
Protect agency. Retrying, changing an idea and inspecting evidence should be normal actions.
Explain after experience. Give the learner something real to reason about before adding formal language.

04 · CURRENT GAME

Probability Carnival

Probability Carnival is a story-driven probability world rather than a numbered staircase.

🔭 The Curious Machine Three Sun tokens and one Moon token. Predict, run trials and watch evidence grow.
🧩 The Machine Builder Build eight tokens and see how the token share changes the chance.
🔎 The Mystery Tent Infer a hidden machine from twelve experimental clues.
⚖️ The Fairness Workshop Compare a balanced machine with an unbalanced one using repeated evidence.

The carnival has no betting, gambling, money or reward-for-risk mechanic. Discovery is the source of excitement.

05 · FOR EVERYONE

Accessibility

Accessibility is a design requirement. Important state is not communicated by colour or canvas alone.

Large targets Keyboard friendly Meaningful labels Visible focus Readable text Reduced motion Responsive layouts Repeat freely

Canvas is used for visual drawing, while important results are also exposed as ordinary HTML text. Small animations respect the user's reduced-motion preference.

06 · TRUST

Privacy & research

Playing is not permission to collect research data. Research participation is explicitly opt-in.

Research collection Only inside the agreed, consent-aware research boundary.
Never part of research collection Passwords, precise location, camera, microphone, uploaded files, advertising identifiers and fingerprinting.

Privacy information remains available without requiring an account. Authentication is disabled for the current physical-game prototype.

07 · ENGINEERING

Technical architecture

The project uses browser-native HTML, CSS and JavaScript with modular game-specific files.

probability-carnival-library.js Probability primitives and repeated trials.
probability-carnival-stories.js Story catalogue, objectives and learning outcomes.
probability-carnival-canvas.js Machine drawing, evidence visuals and small animations.
probability-carnival.js Story state, interactions, completion and reflection.
probability-carnival.css Responsive visual system and accessibility rules.
08 · RELIABILITY

Testing

Static checks Required files, scripts, stylesheets and DOM mount points must exist.
Browser smoke All four Probability Carnival stories are opened and exercised.
Responsive checks Large text, narrow screens and mobile layouts are checked.
Concurrency checks Repeated and queued game actions should not leave stale state behind.
Physical testing Real interaction is still required for size, clarity, wording and comfort.
Acceptance The game is not finished merely because the JavaScript executes.
09 · RESPONSIBILITY

Responsible AI

AI tools may assist with design, implementation, debugging, tests, documentation and review.

AI output is not the authority for correctness, accessibility, privacy, educational quality or legal compliance.

Human review, automated tests and physical use remain part of the build.

10 · BUILD

Development workflow

01 · Discuss 02 · Design 03 · Prototype 04 · Implement 05 · Test 06 · Physically use 07 · Harden 08 · Document

One planned change at a time. Existing games should remain stable while a new game is being built.

Unrelated improvements do not belong in a game change unless they are required for correctness, accessibility or stability.
